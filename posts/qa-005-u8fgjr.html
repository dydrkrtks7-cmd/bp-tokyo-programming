에이전트 구조와 코딩 교육 내용

지난주 화요일 밤 11시, 강남역 카페에서 옆자리 사람이 노트북 화면을 가리키며 친구한테 설명하는 게 들렸다. "이 에이전트가 결과물 넘기면 다음 에이전트가 받아서 검증하고, 또 다음이 리팩토링하고..." four-agent loop, 흔히 말하는 4에이전트 루프 자동화 구조를 설명하더군요. 근데 듣다 보니 핵심을 놓친 부분이 있었다. 그래서 정리해본다.

---

질문 1: "4에이전트 루프가 뭐길래 다들 코딩 스쿨에서 가르치나요?"

간단히 말하면, AI 에이전트 4개가 각각 다른 역할(기획, 코딩, 검증, 배포 같은 식)을 맡고 순환하면서 코드를 만들어내는 구조다. 코딩 스쿨에서 인기인 이유? 결과가 눈에 보이니까. 학생 입장에서 "내가 뭔가 만들었다"는 느낌이 확실하다. 근데 여기서 반골적인 질문을 하나 던져보자. 정말 에이전트가 4개여야 할까? 2개로도 충분한 작업에 4개 붙이면 오버헤드가 쌓인다. 이건 나중에 다시 다룬다.

질문 2: "코딩 스쿨에서 실제로 뭘 배우나요? 수업 내용이 궁금한데"

보통 이런 흐름이다. Python 기초 → API 호출 방법 → LangChain이나 CrewAI 같은 프레임워크로 에이전트 연결 → 실제 프로젝트. 근데 대부분의 스쿨이 "프레임워크 사용법"에 치중한다. 에이전트가 서로 어떤 신호를 주고받을 때 어떤 에러가 나는지, 메모리 관리는 어떻게 할지 이런 실무 디테일은 수업 시간에 스킵되기 일쑤다. 내 경험상, 진짜 막히는 건 프레임워크 쓰는 게 아니라 에이전트 간 상태 동기화다.

질문 3: "이거 진짜 자동화에 쓸 수 있는 건가요? 아니면 그냥 학습용인가요?"

학습용으로 시작하는 건 좋은데, 업무 자동화로 전환하려면 고려할 게 많다. 하나 짚자면, 에이전트 루프에서 가장 흔한 실패 원인은 "에이전트 A의 출력이 에이전트 B의 입력 스펙과 안 맞는 경우"다. 예를 들어, 기획 에이전트가 넘긴 마크다운 형식이 코딩 에이전트가 파싱하는 JSON과 구조가 다르면 루프가 돌아가지도 않는다. 코딩 스쿨에서 이런 케이스를 실제 겪어보는 시간을 주는지 확인하라.

질문 4: "코딩 스쿨 비교할 때 뭘 봐야 하죠?"

여기서 좀 틀어서 말할게. 다들 "커리큘럼"이나 "강사 이력"을 비교하던데, 그건 두 번째로 봐야 한다. 먼저 봐야 할 건 "수강생 프로젝트의 실제 배포 사례"다. github 링크 하나 던져주고 "이 사람이 끝나고 이걸 만들었다"는 증거가 있는지. 증거가 없으면 그 스쿨은 아직 검증 안 된 거다.

---

사실 4에이전트 루프든 뭐든, 중요한 건 "자기 상황에 맞는 복잡도"를 고르는 능력이다. 작성자의 추천 사이트에서 관련 자료 뒤적이다 보면, 굳이 4개 안 써도 되는 상황을 4개로 풀려다 시간 낭비한 사례가 꽤 있다. 나는 잘 모르겠고, 여러분은 어떤가?
